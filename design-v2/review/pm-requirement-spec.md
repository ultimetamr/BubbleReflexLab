# 产品需求与质量契约 · BubbleReflexLab

> revision: 4 · stages: intent + quality_contract · source revisions: pm3 + uxr2 + CR-02 · language: zh-CN · product: PICO Spatial SDK Stage

## 1. 产品意图

BubbleReflexLab 是一局固定 180 秒、舒适优先的中文空间反应小游戏。玩家只记三条规则：普通泡泡拍破、金色泡泡抓住、灰色泡泡不要触碰。体验从 Shared Space 的启动窗开始，经用户明确操作进入 Full Space 的 Stage；头部视点始终静止，挑战来自前方远端泡泡缓慢进入胸前固定互动弧带，而非高速、闪躲或突袭。

## 2. 用户与场景

- 主要用户：初次体验空间游戏、希望三分钟内理解并完成一局的 PICO 用户。
- 使用姿态：站姿优先、坐姿可用；不要求下蹲、侧步、转身或大幅伸手。
- 环境前提：用户已完成系统安全边界；应用不得把虚拟提示当作物理空间安全保证。
- 会话承诺：从按下“开始三分钟”到结算恰好 180 秒游戏时钟；暂停冻结该时钟。

## 3. 不可变规则

| ID | 要求 | 可验收结果 |
|---|---|---|
| R01 | 普通泡泡仅以拍击成功 | 每个普通泡泡最终只有 `hit/miss` 之一 |
| R02 | 金色泡泡仅以抓取成功 | 每个金泡泡最终只有 `grab/miss` 之一 |
| R03 | 灰色泡泡在通过互动弧带前未触碰即成功 | 不产生闪躲任务；最终只有 `untouched/touched` 之一 |
| R04 | 仅在用户前方安全扇形生成 | 生成点满足 yaw ±32°、pitch −18°..+18°、距离 1.6..2.4m，且 z 位于头部前向半空间 |
| R05 | 固定互动弧带 | 中心距头部 0.75–1.05m、相对地面 0.85–1.45m；校准失败不可进入 Stage |
| R06 | 禁止背后/头顶近距/地面下生成 | 边界内外测试分别覆盖 yaw、pitch、distance、floor、forward-dot |
| R07 | 0–30秒为短教程 | 普通、金色、灰色各恰好一次，顺序固定，逐一短提示；速度 0.22m/s |
| R08 | 后150秒为五个固定档 | 30–60/60–90/90–120/120–150/150–180秒分别 T1..T5 |
| R09 | 难度只增数量与组合，不制造高速压力 | 最大同时 5 个；速度上限 0.48m/s；最短生成间隔 1.4秒 |
| R10 | 每30秒换柔和彩色主题与音乐层 | 六段边界原子切换；无突发高音、红闪或加速暗示 |
| R11 | 对象池 | 预热 18 个 BubbleSeed；越界、终局、场景退出均回池；局内不实例化 |
| R12 | 输入 | 手势优先；手柄扳机=拍击、抓取键=抓取、菜单/返回=暂停或取消高风险操作 |
| R13 | 手势瞬时丢失 | 300ms宽限内保持目标但禁新判定；随后显示输入提示；仅当目标 device×OS×SDK 已通过回退验证时启用手柄路径，否则保持暂停并提供安全退出 |
| R14 | 暂停 | 游戏时钟、生成器、轨迹、判定窗、音乐层相位全部冻结；恢复不补发 |
| R15 | 流程 | 开始、校准、短教程、游戏、暂停、退出确认、结算均有明确状态与稳定返回 |
| R16 | 结算 | 准确率、三类成功/总数、铜银金徽章、最高分与保存状态 |
| R17 | 本地保存 | 仅在完整结算时写入最高分；写失败不丢本局结果，可重试 |
| R18 | 可辨识 | 普通=青色圆泡+手掌裂纹；金色=金色环+抓握把手；灰色=哑光六角+禁触横杠；颜色不是唯一编码 |
| R19 | 可达性 | 所有可操作目标至少 56×56dp；正文≥12dp；减弱动效可用；提示有形状+文字 |
| R20 | 退出 | 暂停和结算均可退出 Stage 回 Shared Space；确认对话框可取消 |
| R21 | 校准重做 | 暂停中可重校准；成功后回到冻结的暂停态，不推进时间 |
| R22 | 截图目标 | 教程态与进行态各一张；截图只证明视觉状态，不证明设备安全或性能 |

## 4. 六段节奏与固定档

| 段 | 时间 | 内容 | 同时上限 | 间隔 | 主题/音乐层 |
|---|---:|---|---:|---:|---|
| 教学 | 0–30s | 普通→金色→灰色各一次 | 1 | 固定脚本 | 晨雾青 / 木琴底层 |
| T1 | 30–60s | 单类、留白 | 2 | 3.2s | 杏桃粉 / 加柔垫 |
| T2 | 60–90s | 两类交替 | 3 | 2.7s | 湖水蓝 / 加轻铃 |
| T3 | 90–120s | 三类小组合 | 3 | 2.3s | 薰衣草 / 加柔弦 |
| T4 | 120–150s | 组合与间隔变化 | 4 | 1.8s | 蜜瓜绿 / 加手鼓刷 |
| T5 | 150–180s | 最丰富组合，仍留反应间隙 | 5 | 1.4s | 暖金 / 完整柔和层 |

## 5. 计分与徽章

- `eligible = hitNormal + grabGold + untouchedGray`；`total = spawnedNormal + spawnedGold + spawnedGray`。
- 准确率 `round(eligible / total × 100)`；每个泡泡只产生一次终局 JudgementEvent。
- 分数用于最高分：成功+100；连续成功最多+20柔和奖励；错误不倒扣。
- 铜/银/金：准确率分别达到 60%/80%/92%；不足60%显示“完成”。徽章不掩盖类别统计。

## 6. 成功指标与验收

| 指标 | 门槛 | 证据边界 |
|---|---|---|
| 三规则首轮理解 | 5名目标用户中至少4名在教程后无提示复述正确 | 需未来可用性测试；当前为 provisional |
| 识别反馈 | 有效动作到视觉/触觉/音频确认≤1.2s | 真机 instrumentation |
| 安全生成 | 10,000次确定性采样无扇形外生成；六类边界测试全过 | 下游单测+真机抽查 |
| 暂停冻结 | 暂停10秒后所有实体位置、时间、生成序列不变 | 下游自动测试 |
| 分类辨识 | 教程/游戏截图中三类经形状、材质、符号一眼区分 | Web与真机截图分层验证 |
| 舒适 | 无相机运动、无要求闪躲；5名用户中≥4名报告无不适 | 需真机，不由 Web preview 宣称 |

## 7. 约束、风险与假设

| ID | 假设 | confidence | 若为假时的影响 | 验证计划 | owner / stage |
|---|---|---|---|---|---|
| A1 | 目标 Spatial SDK/BOM 提供可组合的 Stage、手势与手柄事件接口 | medium | 输入回退或 Stage 生命周期需重构，可能阻断实现 | 下游在锁定 BOM 后建立 device×OS×SDK 支持矩阵，编译最小输入探针并在设备/模拟器验证 | downstream technical lead / implementation readiness |
| A2 | 显式 InputArbiter 能在手势丢失时切至已验证手柄输入且不双报 | medium | 300ms 宽限可能产生误判、重复判定或不可恢复停顿 | 自动输入序列测试 + 真机手势丢失/恢复/手柄切换测试；失败则缩小宽限并强制重新武装 | interaction owner + QA / runtime validation |
| A3 | yaw ±32°、pitch −18°..+18°、1.6..2.4m 的 SafeArc 对站/坐用户均舒适 | low | 用户可能需要转头、大幅伸手或出现近头压力 | 5名目标用户站/坐真机舒适测试；只允许收窄体积，不允许放宽背后/地下/近头禁区 | UX research / device usability |
| A4 | 0.22–0.48m/s 与最短1.4秒间隔能维持“温和但逐档丰富” | low | 后段可能仍显紧张，或前段无聊 | 记录每档成功率、主观压力和误触；若压力超标，只降低速度/数量或拉长间隔 | game design / tuning test |
| A5 | 用户能把灰泡“未触碰直到通过”理解为抑制动作，而不是漏判 | low | 灰泡成功缺少可感知性，用户会追碰或闪躲 | 教程口述 + 观察测试；必要时强化禁触横杠与“别碰，等它通过”文案，不增加闪躲动作 | UX research / tutorial test |

- 风险：追踪抖动造成误判 → 300ms grace、重新武装阈值、单终局事件。
- 风险：泡泡越界或对象池泄漏 → 统一 lifecycle receipt 与池不变量。
- 风险：空间拥挤 → 上限5、不可遮挡主提示、冲突组合有最小角距12°。

## 8. 交付边界

本设计包只定义设计事实与 Web 预览；不生成 Android/Kotlin/runtime 代码。真机舒适、追踪、碰撞、性能、音频、180秒定时和最终截图均保持 `not_performed`，直到下游在支持设备验证。

## 8A. Quality Contract

| 维度 | 必须满足 | 非补偿性失败 |
|---|---|---|
| 任务完成 | R01–R22 全部可追踪；教程1次/类；五档固定 | 任何核心规则缺失或变形 |
| 空间价值 | 玩法依赖前方深度接近、双手直接动作与固定弧带 | 可等价压扁为普通2D点击列表 |
| PICO 对齐 | Stage 显式进入/退出；Shared/Full边界清晰；术语/API待版本复核 | 无稳定退出或伪造SDK能力 |
| 领域深度 | SafeArc、Ribbon、Pool、Judgment、Clock、Ledger 有不变量 | 灰泡要求闪躲或多重终局 |
| 舒适安全 | 相机静止、生成全约束、56dp、减弱动效、输入回退 | 背后/地下/近头生成；强制大幅动作 |
| 信息层级 | 当前动作词首要；时间/连击次要；调试信息不进产品态 | 仅颜色编码或遮挡互动弧带 |
| 数据可信 | 本局/最佳分开；保存错误可见；暂无最佳不显示0 | 静默伪造保存成功 |
| 工程可行 | 18对象池、确定性时钟、单终局判定、状态机有退出 | 局内无限实例化或暂停继续更新 |

硬门：`HG-TRACE/HG-REVIEW/HG-DOCS/HG-COMPONENT/HG-PREVIEW/HG-REVISION/HG-FINDINGS/HG-HOST` 必须全 pass；质量分不能抵消硬门。原创性由 Stage 15 `Originality Audit` 独立判定，`templateReuse=false` 是非补偿条件；`HG-HOST` 只能由主线程验收写入。
